## Scout Expedition Design Manual
Version 1.0 – The Safari Expedition Reference

## Philosophy

An expedition should influence Scout's personality, never replace it.
The Expedition is the only layer allowed to express personality. Scout Core expresses behavior.

Scout does not organize files.

Scout helps people discover their files.

Every expedition is a guided journey of discovery.

The user is never expected to understand their files before beginning. Scout gradually reveals patterns, explains what was discovered, shows the evidence, and finally recommends actions.

The expedition is designed to replace uncertainty with confidence.

Nothing is changed until the user understands why.


##Core Principles

Every expedition must satisfy the following principles.

Discovery before recommendation

Scout never begins with:

Here is what I will do.

Scout always begins with:

Here is what I discovered.

Recommendations are earned.


##Explain before asking for trust

Every recommendation must answer four questions.

What did Scout notice?

Why does it matter?

What evidence supports it?

What can be done?

The user should never wonder where a recommendation came from.


## Conversation is always available

Buttons provide speed.

Conversation provides freedom.

Every action available through buttons should also be reachable naturally through conversation.

The conversation is never secondary.


## The user always remains in control

Scout never silently changes files.

Every expedition ends with a preview.

Approval always belongs to the user.



## Expedition Architecture

Every expedition shares the same structure.

Only the presentation changes.

Header

Observation Panel

Discovery Workspace

Conversation

Status Bar

These regions never fundamentally change.

Only their appearance.


## The Header

The header establishes the expedition.

It should immediately answer:

Where am I?

The left side always contains:

Scout

The typography changes to match the expedition.

Examples

Safari
Rustic carved explorer lettering

Space
Clean futuristic lettering

Museum
Elegant engraved serif

Underwater
Weathered nautical lettering

etc.

Immediately beside Scout is artwork representing Scout entering that world.

Not decoration.

A story.

Safari example:

Scout parts jungle leaves to reveal the user's files hidden inside the jungle.

The user's files are literally what Scout is discovering.


## Progress

The center of the header displays expedition progress.

Progress is never a percentage.

It is visual storytelling.

Safari

Footprints appear while Scout is discovering.

Each new footprint appears as progress advances.

The path varies slightly every expedition.

Just enough to feel natural.

Scout doesn't walk exactly the same trail every time.

Completion is represented by reaching camp.


## Living Environment

Every expedition has one persistent animated element.

Safari

Campfire

The fire flickers continuously.

Even while Scout is idle.

The expedition feels alive.

Future expeditions should include equivalent ambient motion.

Never distracting.

Always comforting.


## Observation Panel

The Observation Panel answers one question.

What has Scout noticed?

Observations are discoveries.

Never commands.

Never tasks.

Every observation appears as a button.

Each button begins with:

"I noticed..."

Examples

Music Collection

Album Artwork

Related Files

Project Type

Selecting an observation changes the Discovery Workspace.

Not the expedition.


## Discovery Workspace

This is the heart of every expedition.

It tells the story of one discovery.

It should always answer the same questions.

Current Discovery

What did Scout notice?

Why I noticed this

Explain Scout's reasoning.

Teach.

Build confidence.

What I found

Evidence.

Counts.

Statistics.

Representative examples.

Interactive buttons that allow the user to change focus without leaving the discovery.

Things we could do

Possible improvements.

These are recommendations.

Not commitments.

Each recommendation can be expanded for more detail.


## Conversation

Conversation is Scout's personality.

Buttons are shortcuts.

Conversation is companionship.

Scout speaks naturally.

Not excessively.

Not mechanically.

Conversation should feel like an experienced guide walking beside the user.

The conversation should react to everything.

Folder chosen.

Discovery selected.

Recommendation expanded.

Preview opened.

Organization completed.

Conversation should never repeat information already visible unless it adds understanding.


## Status Bar

The status bar provides immediate feedback.

Examples

Tracking music collections...

67 songs found.

18 albums identified.

Halfway to camp.

The status bar should communicate activity at a glance.


## Expedition Separation

An expedition is not responsible for file intelligence.

Scout Core discovers information.

Experts analyze domains.

Expeditions present discoveries.

Therefore:

Core

"What was found?"

Experts

"Why was it found?"

Expedition

"How should the user experience this?"

This separation must never be violated.


## Animation Guidelines

Animation exists to support emotion.

Never spectacle.

Safari examples

Footprints appear naturally.

Fire flickers continuously.

Leaves sway gently.

Nothing flashes.

Nothing spins.

Nothing competes with the user's work.

## Sound (Future)

Every expedition may include ambient sound.

Safari

Birds.

Wind.

Fire.

Footsteps.

Soft.

Optional.

Never required.


## The Goal

A successful expedition should leave the user feeling:

"Scout helped me understand my files."

not

"Scout renamed my files."

## most important

An expedition is not a skin applied to Scout. It is a world that Scout temporarily 
invites the user into while they discover, understand, and organize their files together.




## The Expedition Contract

1. Every expedition must preserve Scout's identity while expressing a unique personality.

An expedition may change:

Visual appearance
Artwork
Color palette
Typography
Icons
Animation
Ambient sound
Vocabulary
Sentence rhythm
Tone
Metaphors

An expedition must never change:

Scout's honesty
Scout's patience
Scout's curiosity
Scout's respect for user control
Scout's habit of explaining before acting
Scout's commitment to showing a preview before making changes

This becomes the constitution for every future expedition.

2. World Before Widgets

I think this may become one of the most important rules in the manual.

World Before Widgets

When designing an expedition, do not begin by asking:

What should this button look like?

Begin by asking:

Who is Scout in this world?

Every visual element should naturally emerge from that answer.

Example:

Safari

Footprints are not a progress bar.

They are the guide's journey.

Museum

Cards are not buttons.

They are exhibits.

Space

Observations are not panels.

They are sensor readings.

The world should explain the interface.

Not the other way around.

3. Living Worlds

This one comes directly from your campfire idea.

Living Worlds

Every expedition should feel alive even when Scout is idle.

Life comes from subtle ambient motion.

Examples

Safari

Campfire flickers.
Leaves sway.
Light changes slightly.

Arctic

Snow drifts.
Breath condenses.
Aurora moves slowly.

Space

Stars drift.
Consoles pulse softly.
Radar sweeps.

Animation exists to create atmosphere, not entertainment.

If the user notices the animation more than their work, it is too strong.

4. Expedition Vocabulary

This one will save an enormous amount of inconsistency later.

Instead of inventing text as we go, every expedition should define its own language.

For example:

    Wilderness Guide

Primary Verb:
    Discover

    Notice

Investigation:
    Explore

Recommendation:
    Suggest

Progress:
    Follow the trail

    Reach camp

Celebration:
    Another successful expedition.

Windows 10 Expedition:

    Helpful Assistant

Primary Verb:
    Find

Observation:
    Notice

    Show

Recommendation:
    Help

Progress:
    Working...

    You're all set!

Arctic:

    Polar Explorer

    Survey

    Marker

    Examine

## The user is not choosing a theme. The user is choosing the world in which they would 
like Scout to accompany them as well as the version of scout that matches their needs.


## One last guideline

If a feature would still make sense after replacing every visual asset with gray boxes, 
it probably belongs in Scout Core. If the feature only makes sense because of the chosen world, 
it probably belongs to the Expedition.

## Every Expedition Starts and Finishes at Camp

Camp is Scout's home and the user's place of comfort.

Every expedition begins with a welcome.

Every expedition returns with understanding.

Camp is where journeys begin, where discoveries are reflected upon, 
and where the user decides when it's time to head out again.

Scout never leaves the user stranded at the end of a task.

Scout always walks them back to camp.

## What is Camp?

Before writing any XAML, I would define Camp as an abstraction.

Not "a campfire."

Not "a log cabin."

Not "a header."

Instead:

Camp is the user's home base within an expedition.

Every expedition has one.

Its appearance changes.

Its purpose does not.

Camp always provides five things:

A Welcome
"I'm glad you're here."
The expedition greets the user.
Orientation
"Where are we?"
Which expedition is active?
What kind of work is this world designed for?
Readiness
"What would you like to do today?"
The user chooses when to begin.
Reflection
After an expedition, Camp is where Scout summarizes what was accomplished.
A Sense of Home
The user always returns here.
Camp never feels like a dead end.

Those five responsibilities belong to Camp, regardless of whether it's Safari, 
Arctic, Windows, Space, or something we haven't imagined yet.

## Camp Framework
Camp

Camp is the emotional home of every expedition.

Every expedition begins at camp.

Every expedition returns to camp.

Camp is a place of safety, reflection, and preparation.

While every expedition has its own appearance, the purpose of Camp never changes.

# Greeting

A greeting always contains two parts.

# A Welcome

The welcome establishes the tone of the expedition.

Examples:

Safari

"I'm glad you're here."

Arctic

"Welcome back. The weather looks favorable today."

Archaeology

"Good to see you again."

Windows

"Welcome back."

The wording changes.

The purpose does not.

An Invitation

Every greeting ends with a themed question.

Not

"Choose a folder."

Instead

Safari

"What would you like to discover today?"

Archaeology

"What would you like to uncover?"

Mining

"What would you like to dig up?"

Library

"What would you like to explore?"

Museum

"What would you like to examine?"

The invitation defines the expedition before any work begins.

# Scout

There is only one Scout.

Scout's identity never changes.

What changes is the way Scout expresses that identity.

Instead of asking:

Who is the guide?

The framework asks:

How does Scout feel in this world?

Examples:

Safari

calm
patient
observant

Windows

familiar
practical
encouraging

Arctic

concise
prepared
resilient

The personality shifts.

The character does not.

# Expedition Identity

Every expedition has a clearly stated identity.

The user should immediately understand:

where they are
what kind of discoveries this expedition specializes in
why they chose this expedition

The expedition should never need explanation after the first few seconds.

# Invitation

The invitation answers one question.

Why should I begin this journey?

It encourages curiosity without directing the user.

Examples:

"What would you like to discover today?"

"What mystery shall we investigate?"

"What would you like to organize?"

"What would you like to restore?"

# Atmosphere

Every expedition defines its atmosphere.

Atmosphere may include:

ambient sound
subtle animation
lighting
environmental motion
background artwork

Atmosphere supports immersion.

It never distracts from the user's work.

# Accessibility

All atmospheric effects should be individually adjustable.

Users should be able to:

mute ambient sound
reduce animation
simplify backgrounds

Comfort always takes priority over immersion.

I particularly like your idea of making this part of the framework instead of a Safari-specific option. It means every expedition automatically inherits accessibility as a first-class feature rather than treating it as an afterthought.

# Returning to Camp

Camp is safe and never changes. The fire in the corner is always burning and welcoming.

# Camp is Constant

No matter how successful or difficult the expedition was...

Camp is unchanged.

The fire is still burning.

Scout is still there.

Nothing has been lost.

Nothing has become unfamiliar.

The user returns to exactly the place they left.

That consistency creates trust.

## Never animate around bad architecture. 
1. Fix the architecture first.
2. Every expedition is a stage. Every visual object is an actor.
3. Nothing moves unless it has a reason to move.
4. Build one thing well before building ten things quickly.
5. Polish is a feature. Small touches that communicate life and quality 
   are part of the product, not optional decoration.

   ## Animate the living part, never the object that contains it.
